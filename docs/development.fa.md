# راه‌اندازی محلی Infinitycolor

[English](development.md) · [معرفی مخزن](../README.md)

## ابزارها و تنظیمات

به Node.js **20.19 یا جدیدتر از سری 20.x**، Git، pnpm **10.28.2** و Docker
Compose نیاز دارید. حداکثر نسخهٔ مجاز Node در بک‌اند، 20 است. در ویندوز از
PowerShell و Docker Desktop با WSL2 استفاده کنید. اگر داخل WSL2 کار می‌کنید،
مخزن و وابستگی‌ها را همان‌جا نگه دارید؛ با تغییر سیستم‌عامل، دوباره نصب کنید.

اگر Corepack نصب نیست:

```bash
npm install --global corepack
corepack pnpm --version
```

از دکمهٔ Clone در GitLab یا `glab` واردشده استفاده کنید. از ریشهٔ مخزن، در
Bash یا PowerShell:

```bash
glab repo clone bel4/infinity
cd infinity
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @repo/auth-core build
node scripts/setup-dev-env.mjs
node scripts/setup-dev-env.mjs --check
docker compose --env-file apps/backend/.env -f compose.dev.yml up -d
docker compose --env-file apps/backend/.env -f compose.dev.yml ps
```

صبر کنید PostgreSQL healthy شود. ابزار راه‌اندازی `apps/backend/.env` و فایل‌های
`.env.local` برنامه‌های وب را در صورت نبودن می‌سازد، کلیدهای محلی و رمزهای هماهنگ
پایگاه داده را تولید و فایل‌های موجود را حفظ می‌کند. `--check` فقط وجود فایل‌ها
را بررسی می‌کند. از lockfile فعلی pnpm استفاده کنید و در workspace، npm install
اجرا نکنید. اطلاعات سرویس‌های جانبی به‌صورت پیش‌فرض خالی می‌مانند.

[Compose توسعه](../compose.dev.yml) ذخیره‌سازی محلی این پروژه را اجرا می‌کند:
PostgreSQL روی **5432** و Redis روی **6379**، فقط روی loopback.
Redis جداگانهٔ صف هم روی پورت 6381، با سیاست noeviction اجرا می‌شود.

قبل از شروع، بستهٔ [`@repo/auth-core`](../packages/auth-core) را build کنید؛
برنامه‌ها فایل‌های کامپایل‌شدهٔ `dist` و `dist-cjs` آن را می‌خوانند و `dev` آن‌ها
را نمی‌سازد. پس از تغییر کد این بسته، build را دوباره اجرا کنید.

## اجرا و بررسی شروع

در ترمینال اول، از ریشهٔ مخزن:

```bash
corepack pnpm --filter @repo/backend dev
```

پس از آماده شدن بک‌اند، در http://localhost:1337/admin حساب مدیر محلی Strapi
بسازید. در ترمینال دوم، از ریشه:

```bash
corepack pnpm --filter @repo/frontend dev
```

http://localhost:1337/api/_health را باز کنید؛ باید `checks.db="ok"` و
`checks.redis="ok"` ببینید. هر دو بررسی وابستگی باید `ok` باشند.
http://localhost:2888 را باز کنید و نمایش سایت و نبود خطای اتصال API را بررسی
کنید. کامپایل اولین اجرا ممکن است زمان ببرد.

## Auth و برنامه‌های دیگر

برای دیدن فروشگاه، اجرای بک‌اند و فرانت‌اند کافی است. برای ورود با رمز، پنل
مدیریت یا بخش اجتماعی، ابتدا ساختار Auth را در همان پایگاه محلی `infinity_local`
آماده کنید:

```bash
node --env-file=apps/auth/.env.local apps/auth/scripts/apply-migration.mjs
```

مقدار تولیدشدهٔ `AUTH_MIGRATION_DATABASE_URL` با کاربر مالک پایگاه داده وصل
می‌شود؛ `AUTH_DATABASE_URL` از نقش جداگانهٔ `infinity_auth_app` استفاده می‌کند.
اسکریپت نقش و ساختار Auth و migrationهای افزایشی را آماده می‌کند. تبدیل URL به
مسیر فایل در این اسکریپت ممکن است مسیر درایو ویندوز را رد کند؛ در این حالت کل
محیط را داخل WSL2، با وابستگی‌های نصب‌شده در همان‌جا، اجرا کنید.

در ترمینال‌های جداگانه، از ریشهٔ مخزن:

```bash
corepack pnpm --filter @repo/auth dev
corepack pnpm --filter @repo/admin dev
corepack pnpm --filter @repo/social dev
```

| برنامه | نشانی |
| --- | --- |
| Auth | http://localhost:2889 |
| پنل مدیریت | http://localhost:2891 |
| بخش اجتماعی | http://localhost:2890 |

`AUTH_STRAPI_BRIDGE_SECRET` باید در بک‌اند و Auth یکسان باشد؛ همیشه از نشانی‌های
تنظیم‌شدهٔ `localhost` استفاده کنید. رمزها و نقش‌های کاری در Strapi هستند؛ Auth
هویت‌های متصل و نشست‌ها را مدیریت می‌کند. [معماری](auth/architecture.md) و
[راهنمای عملیات](auth/operations.md) را ببینید.

## اولین استفاده و داده‌های محلی

حساب مدیر Strapi برای دیدن Content Manager محلی است؛ با حساب مشتری فروشگاه
یا مدیر کاری فرق دارد. [راه‌اندازی بک‌اند](../apps/backend/src/index.ts) نقش‌های
کاری و مجوز عمومی خواندن را آماده می‌کند، ولی کاتالوگ کامل یا حساب ورود
آزمایشی نمی‌سازد.

تا پیش از دریافت دادهٔ نمونه، این موارد را بررسی کنید:

1. پنل Strapi باز شود و مجموعه‌های Product، Variation و Stock در دسترس باشند.
2. `http://localhost:1337/api/products` پاسخ JSON بدهد؛ کاتالوگ خالی طبیعی است.
   برای 403، خطاهای شروع و مجوزها را بررسی کنید؛ همهٔ مجوزها را عمومی نکنید.
3. فروشگاه نمایش داده شود و تست زیر، محاسبهٔ موجودی قابل‌فروش پس از کسر رزروها را
   بدون سرویس خارجی یا پایگاه دادهٔ پرشده بررسی کند.

```bash
corepack pnpm --filter @repo/backend test:unit --runInBand src/api/cart/services/lib/__tests__/stock-available.spec.ts
```

اسکریپت نگهداری‌شده‌ای برای ساخت دادهٔ نمایشی عمومی وجود ندارد. `seed:e2e` مخصوص
تست است و قواعد پاک‌سازی و کنترل مقصد دارد؛ برای راه‌اندازی روزمره نیست.
اسکریپت قدیمی `seed:admin` توکن Master API می‌خواهد و شناسهٔ نقش local-user را 2
فرض می‌کند؛ حساب معتبر پنل مدیریت فعلی را تضمین نمی‌کند. برای پیدا کردن راه
ورود، این دستورها را روی پایگاه دادهٔ کاری خودتان اجرا نکنید.

از مسئول مخزن **دادهٔ آزمایشی مخصوص محیط محلی** با این موارد بگیرید:

- یک دسته، یک محصول `Active` با نامک یکتا و تصویر، یک تنوع متصل با SKU یکتا
  و قیمت، و موجودی متصل با `Count > 0` و `reservedCount = 0`. نشانی یا نامک
  محصول را هم بگیرید تا بتوانید آن را پیدا کنید.
- تنظیمات و روابط منوی محلی لازم برای نمایش محصول. مجوز عمومی خواندن محصول
  و دسته باید با کد راه‌اندازی هماهنگ باشد.
- برای کار روی سبد و تسویه، مشتری، نشانی، استان/شهر و روش ارسال محلی ساختگی؛
  تنظیمات آزمایشی پرداخت یا پیامک باید جداگانه مشخص شوند.

پس از دریافت داده‌ها، محصول را باز کنید، تنوع را انتخاب و به سبد اضافه کنید؛
قیمت و موجودی نمایش‌داده‌شده باید با دادهٔ آزمایشی یکسان باشد.

برای کار روی حساب یا مدیریت، مسئول مخزن باید یک کاربر مشتری ساختگی، تأییدشده
و فعال در Users & Permissions استرپی و یک کاربر جداگانهٔ همکار با نقش مناسب کار
شما، اطلاعات ورود با رمز و اتصال درست هویت‌ها از طریق Auth محلی بدهد. قبل از
بررسی ورود فروشگاه یا پنل مدیریت روی 2891، Auth را اجرا کنید. مسیرهای پیامک و
درگاه پرداخت به تنظیمات مشخص سرویس توسعه نیاز دارند؛ ابزار راه‌اندازی آن‌ها
را فراهم نمی‌کند.

## مسیر کد و بررسی‌های مرتبط

| کار | مسیر کد | بررسی‌ها |
| --- | --- | --- |
| فروشگاه و حساب کاربری | [کد فرانت‌اند](../apps/frontend/src) | lint، بررسی نوع‌ها، تست و build فرانت‌اند و مسیر مرورگر مرتبط |
| موجودی، کاتالوگ و سفارش | [APIهای بک‌اند](../apps/backend/src/api) | بررسی نوع‌ها، تست واحد و build بک‌اند و API محلی |
| نقش‌ها و راه‌اندازی | [شروع بک‌اند](../apps/backend/src/index.ts) | بررسی‌های بک‌اند و کارهای مجاز/غیرمجاز با کاربران محلی |
| سرویس‌های محلی | [ابزار راه‌اندازی](../scripts/setup-dev-env.mjs)، [Compose](../compose.dev.yml) | وجود تنظیمات، سلامت ذخیره‌سازی و API |

```bash
corepack pnpm --filter @repo/frontend lint
corepack pnpm --filter @repo/frontend check-types
corepack pnpm --filter @repo/frontend test --runInBand
corepack pnpm --filter @repo/frontend build
corepack pnpm --filter @repo/backend check-types
corepack pnpm --filter @repo/backend test --runInBand
corepack pnpm --filter @repo/backend build
```

بررسی‌های بستهٔ درگیر را اجرا کنید؛ دستورهای ریشهٔ `lint`، `check-types`، `test`
و `build` کل workspace را با Turbo بررسی می‌کنند. [تست واحد محدود](../apps/backend/src/api/cart/services/lib/__tests__/stock-available.spec.ts)
بالا قبل از آماده شدن کاتالوگ و حساب‌ها قابل اجراست. تست پایگاه دادهٔ واقعی،
مرورگر، واردکننده و سرویس‌های جانبی، داده و مقصد مستقل خودشان را می‌خواهند و
جزو دستورهای اولین اجرا نیستند.

## توقف، اجرای دوباره و رفع خطا

هر برنامه را با Ctrl+C متوقف کنید. برای توقف ذخیره‌سازی و حفظ داده‌ها:

```bash
docker compose --env-file apps/backend/.env -f compose.dev.yml down
```

برای ادامه، دستورهای `up -d` و `ps` بالا را اجرا کنید، صبر کنید سرویس‌ها سالم
شوند و سپس برنامه‌ها را در ترمینال‌هایشان اجرا کنید. بعد از تغییر تنظیمات،
برنامه را دوباره اجرا کنید. `down -v` راه عادی رفع خطا نیست.

- **اتصال پایگاه داده یا cache شکست می‌خورد:** خروجی `ps` و دستور
  `docker compose --env-file apps/backend/.env -f compose.dev.yml logs --tail=80 postgres redis`
  را ببینید. `DATABASE_PORT` و `REDIS_URL` بک‌اند را با 5432 و 6379 مقایسه کنید.
- **رمز پایگاه داده رد می‌شود:** volume رمز اولیهٔ خودش را نگه می‌دارد و ابزار
  هم فایل‌های محلی موجود را حفظ می‌کند. این دو را هماهنگ کنید؛ تغییر `.env`
  به‌تنهایی رمز پایگاه داده را عوض نمی‌کند.
- **فروشگاه به API اشتباه وصل است:** مقدار
  `NEXT_PUBLIC_API_BASE_URL=http://localhost:1337/api` و `STRAPI_INTERNAL_URL`
  محلی متناظر را بررسی کنید. `.env.local` تنظیمات محلی فرانت‌اند را تعیین
  می‌کند. هشدار نبودن `main.env` قدیمی، درخواست فایل محیط عملیاتی نیست.
- **کاتالوگ خالی است یا ورود رد می‌شود:** پیش‌نیازهای داده و حساب بالا را ببینید.
  حساب تازهٔ مدیر Strapi، کاربر کاری فروشگاه نیست.
- **پورت اشغال است:** 1337 و 2888 در فروشگاه‌ها مشترک‌اند. یک محیط را در هر زمان
  اجرا کنید یا پورت و همهٔ نشانی‌های مرتبط را هماهنگ تغییر دهید؛ فرایند پروژهٔ
  دیگری را بدون شناسایی نبندید.
- **ماژول کامپایل‌شدهٔ @repo/auth-core پیدا نمی‌شود:** بعد از نصب یا تغییر بستهٔ
  مشترک، build آن را مطابق بالا تکرار و برنامه را دوباره اجرا کنید.
- **ساخت shim مجاز نیست:** مستقیماً `corepack pnpm` را اجرا کنید. برای خطای نصب،
  قبل از تغییر lockfile نسخهٔ Node و pnpm را بررسی کنید.
